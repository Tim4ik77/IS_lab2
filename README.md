# Информационная система билетов — ЛР1 и ЛР2

Задания: [ЛР1](lw1.txt), [ЛР2](lw2.txt). Spring MVC, JPA/EclipseLink, PostgreSQL и React.

Система поддерживает CRUD билетов и справочников, поиск по ID, таблицу с фильтрацией, сортировкой и пагинацией, специальные операции БД, транзакционный импорт JSON и историю импорта с разграничением по ролям.

## База данных

Создайте PostgreSQL-базу и пользователя. Для пустой базы выполните из корня проекта:

```powershell
psql -h localhost -U tickets -d tickets -v ON_ERROR_STOP=1 -f create_db.sql
psql -h localhost -U tickets -d tickets -v ON_ERROR_STOP=1 -f migrations/002_import.sql
```

Для существующей базы ЛР1 выполните только миграцию. Перед запуском устраните дубликаты названий событий и площадок: Java-проверка при старте обнаруживает их. Уникальность названий без учёта регистра и крайних пробелов проверяется в бизнес-логике, без UNIQUE в БД.

## Сборка и запуск

Нужны Java 17+, Node.js 22+ и PostgreSQL. Maven скачивается обёрткой из `backend`.

```powershell
cd frontend
npm ci
npm run build
cd ../backend
.\mvnw.cmd package
cd ..
$env:DB_URL = 'jdbc:postgresql://localhost:5432/tickets'
$env:DB_USER = 'tickets'
$env:DB_PASSWORD = 'your-password'
java -jar backend/target/tickets-1.0.0.jar
```

Откройте http://127.0.0.1:8080. JAR содержит собранный интерфейс. Для разработки: `npm run dev` из `frontend`; `/api` проксируется на порт 8080.

Кафедральный сервер: профиль `remote` использует `DB_HOST` (по умолчанию `pg`), `DB_PORT` (`5432`), `DB_NAME` (`studs`), `DB_SCHEMA` (`ticket_lab1`), а также обязательные `DB_USER` и `DB_PASSWORD`. Создайте собственную схему и выполните SQL в ней, задав `search_path`. Запуск: `java -jar backend/target/tickets-1.0.0.jar --spring.profiles.active=remote`. `SERVER_ADDRESS` определяет адрес прослушивания в этом профиле, `SERVER_PORT` — порт приложения.

## Вход

| Логин | Учебный пароль | Роль | Переменная замены пароля |
|---|---|---|---|
| user | user-lab2 | Пользователь | USER_PASSWORD |
| user2 | user2-lab2 | Пользователь | USER2_PASSWORD |
| admin | admin-lab2 | Администратор | ADMIN_PASSWORD |
| admin2 | admin2-lab2 | Администратор | ADMIN2_PASSWORD |

Пользователь видит только собственную историю импорта, администратор — все операции. Пароли задаются при запуске сервера; для удалённого размещения используйте собственные пароли и HTTPS. Локальные секреты в репозиторий не входят.

## Импорт

Страница «Импорт и история» принимает UTF-8 JSON: массив из 1–1000 билетов, до 5 МиБ. [Пример файла](frontend/public/import-example.json) доступен также в интерфейсе.

В каждой записи задаются поля билета и вложенные `coordinates`, `event`, `venue`; необязательный `person` содержит обязательную `location`. ID и дата создания назначаются сервером. Ограничения полей соответствуют модели ЛР1; названия событий и площадок дополнительно не могут состоять из пробелов. Неизвестные поля, неверные enum и дробные значения целочисленных полей отклоняются.

Существующие события и площадки переиспользуются по нормализованному названию, если остальные поля совпадают; иначе весь импорт отменяется. Координаты, человек и локация создаются для каждой записи заново. При любой ошибке ни один объект файла не сохраняется. Количество в успешной операции — число билетов; повторная успешная загрузка создаёт новые билеты.

История содержит ID операции, статус, владельца и количество добавленных билетов только при успехе, а также имя файла, время и причину ошибки. Ошибка записывается отдельной транзакцией после отката; успех — вместе с объектами. При аварийном завершении процесса запись может остаться `RUNNING`.

Для редактирования и удаления билета API требует заголовок `If-Match` с текущим `version`; интерфейс передаёт его автоматически. Конфликт возвращает 409, отсутствие версии — 428. ID и версии в JSON возвращаются строками для сохранения точности Java Long.

## JMeter и изоляция

Обязательный сценарий: [lab2.jmx](tests/jmeter/lab2.jmx) и используемый им `scenario.groovy`. Нужен Apache JMeter 5.6.3. Запускайте на отдельной тестовой БД: сценарий создаёт данные.

Из корня проекта при запущенном backend:

```powershell
New-Item -ItemType Directory -Force tests/results
jmeter -n -t tests/jmeter/lab2.jmx -l tests/results/run.jtl -j tests/results/run.log -Jrounds=5
```

Параметры: `-JbaseUrl=http://127.0.0.1:8080`, `-JscriptDir=tests/jmeter`, `-JoutDir=tests/results`, `-Jrounds=5`. При изменённых паролях задайте `-JuserPassword=...`, `-Juser2Password=...`, `-JadminPassword=...`, `-Jadmin2Password=...`. При запуске через GUI задайте `scriptDir` абсолютным путём либо запускайте GUI из корня проекта.

Четыре потока имитируют пользователей и администраторов. Проверяются CRUD, успешный импорт и откат, update/update, delete/delete, update/delete, одинаковые уникальные имена и создание против импорта. Финальная проверка контролирует число победителей и состояние данных. Успех: `Err: 0` и `success=true` во всех строках JTL, а не только код завершения JMeter.

[Обоснование изоляции и результаты исследования](docs/transaction-report.md). Генерируемые результаты, сборки и зависимости исключены из Git. Дополнительные тестовые комплекты и служебные скрипты в эту версию не входят.
